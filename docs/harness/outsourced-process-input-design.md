# 외주 공정 입력 설계 (2026-10-16)

규정 근거: [outsourced-processes-regulation-check.md](outsourced-processes-regulation-check.md). 요지만 다시 적는다.

- 철강제품 경계 **안**의 공정(열처리·코팅·용융아연도금 등)을 다른 사업장·외주사가 하고 물건이 돌아오면 **우리 사업장에서 일어난 것처럼** 다룬다(EC Q&A 2026-05-27, 4.31). 돌아온 부품은 전구물질이 아니다.
- 그러므로 외주처가 그 공정에서 우리 부품 몫으로 쓴 연료·전력은 **우리 공정의 직접·간접배출에 그대로 더한다.**
- 외주처 자료가 부족하면 보수적 추정(부속서 II A.1 5항). 회사 전체 연료만 있을 때의 나누기는 부속서 II A.3 · 부속서 III A.1(식 41·42) · A.2를 따른다 — 앱의 공용 계량기 나누기와 같은 논리.
- 경계 **밖** 공정(전기도금·절단·용접·마무리)은 외주여도 넣지 않는다.

## 1. 설계 원칙

1. **엔진은 건드리지 않는다.** 외주 몫은 「우리 공정에 붙는 보통의 연료 배출원(SourceStream)」으로 저장한다. 엔진·EU 엑셀·산정보고서의 직접배출 합계가 이미 그것을 읽는다. 새 필드는 출처·근거를 남기는 **메타데이터**일 뿐이다.
2. **옛 앱·옛 백업과 호환한다.** 새 필드는 모두 선택이고, 계산 결과(`activity_data`)는 보통 배출원과 같은 자리에 저장한다(전력 공용 계량기 `electricity_shared_meter`와 같은 방식 — 모르는 앱도 같은 숫자를 낸다). **백업 `format_version`을 올리지 않는다.**
3. **앱이 지어내지 않는다.** 외주 몫 숫자는 사용자가 넣은 값에서 공식대로만 계산하고, 추정이면 사유·근거 없이는 저장하지 않으며 「확인 필요」로 남긴다(기존 INDIRECT_ESTIMATE와 같은 원칙).
4. **경계 밖 공정은 받지 않는다.** 공정 종류가 전기도금·절단·용접·마무리이면 저장 대신 「경계 밖이라 넣지 않습니다」를 낸다.
5. **전구물질 칸에 넣지 않는다.** 5_구매강재는 「다른 사업장이 만든 CBAM 원료」용이다. 외주 임가공 반환품을 거기 넣으면 외주 전체를 기본값으로 이중계산한다 — 서식·화면 안내에도 적는다.

## 2. 자료 모양

`SourceStream`에 선택 필드 하나를 더한다(`src/lib/local-db.ts`).

```ts
export type OutsourcedTechnique =
  | "HEAT_TREATMENT"        // 열처리·소둔·QT (경계 안)
  | "ZINC_FLAKE_COATING"    // 다크로·지오메트 등 비전해 아연 플레이크 (coating, 경계 안)
  | "HOT_DIP_GALVANIZING"   // 용융아연도금 (galvanizing, 경계 안)
  | "OTHER_COATING"         // 그 밖의 코팅 (경계 안, 근거 필요)
  | "ELECTROPLATING";       // 전기도금 (plating, 경계 밖 → 저장 거부)

export type OutsourcedBasis =
  | "METERED_LINE"          // 그 공정 설비의 계량값(외주처 제공) — A.3(1)
  | "RECONSTRUCTED"         // 설비 소비율 × 가동시간으로 재구성 후 고지서 총량에 맞춤 — A.3(2)(b), III A.1 식 41·42
  | "OUTPUT_MASS"           // 같은 설비·같은 조건의 처리 중량 비율 — III A.2
  | "CONSERVATIVE_ESTIMATE";// 객관적 근거가 있는 보수적 추정 — II A.1 5항

export interface OutsourcedProcessInfo {
  subcontractor: string;            // 외주처 이름
  technique: OutsourcedTechnique;
  technique_evidence?: string;      // 전해 여부 등 분류 근거(공정 설명서·ISO 10683/4042 등). 코팅·도금 구분에는 필수
  basis: OutsourcedBasis;
  /** 계산 입력 — 방법별로 일부만 쓴다 */
  company_total?: number;           // 외주처 전체(또는 해당 계량기) 연료량 — 고지서 총량. 활동량과 같은 단위
  line_quantity?: number;           // 그 공정 설비의 연료량(METERED_LINE·OUTPUT_MASS) — 같은 단위
  our_throughput_t?: number;        // 우리 부품 처리량(t)
  line_throughput_t?: number;       // 같은 설비 전체 처리량(t)
  equipment?: Array<{ name: string; hours: number; rate_per_h: number; ours?: boolean }>; // RECONSTRUCTED
  note: string;                     // 근거·가정(추정이면 필수)
  evidence?: string;                // 외주처 고지서·가동기록·계약서 등
  to_confirm: boolean;              // 확인 필요(추정이거나 근거가 비어 있음)
}
// SourceStream 안: outsourced?: OutsourcedProcessInfo;
```

- 저장 행: `process_id` = 우리 공정, `stream_type` = FUEL, `activity_data` = 아래 계산 결과(우리 몫), 이름 = 「(외주) 외주처명 — 공정」. 연료 종류·열량·배출계수는 기존 연료 입력과 같다.
- 외주 몫은 **우리 공정마다 한 행**(여러 공정에 걸쳐 처리하면 처리량 비율로 행을 나눈다 — 기존 공용 나누기 도구를 재사용).

## 3. 계산 (`src/lib/outsourced-process.ts`, 순수 함수)

| 방법 | 입력 | 우리 몫 (활동량) | 근거 |
|---|---|---|---|
| METERED_LINE | 그 공정 계량값 Q | Q × (우리 처리량 / 같은 설비 전체 처리량). 설비 전용 계량이고 우리만 쓰면 Q 그대로 | A.3(1), III A.2 |
| RECONSTRUCTED | 설비별 (시간 × 소비율), 회사 총량 T | 재구성 합 R = Σ(h×r). 보정계수 RecF = T / R. 우리 몫 = (우리 설비 재구성) × RecF | A.3(2)(b), III A.1 식 41·42 |
| OUTPUT_MASS | 설비 연료량 Q, 처리량 | Q × 우리 처리량 / 설비 전체 처리량 | III A.2 |
| CONSERVATIVE_ESTIMATE | 정격 용량·시간·부하율 등 | 입력 그대로(사용자 계산) — `note` 필수, 항상 `to_confirm` | II A.1 5항 |

검증 규칙: 모든 수는 0 이상이고 분모는 0보다 크다. 우리 처리량 ≤ 전체 처리량. RECONSTRUCTED는 `T`가 있어야 하고 재구성 합이 `T`보다 크게 어긋나면(±20% 초과) 설비 목록을 점검하라고 알린다. 보수적 추정과 RECONSTRUCTED·OUTPUT_MASS에서 설비 사양을 못 대면 `to_confirm`.

**테스트 기준값**(사용자가 준 검토 메모의 가상 사례, 규정 해석이 같음):
- 사례 A: T = 120,000 Nm³, 설비 (우리 600 h × 50, 타사 900 h × 50, 기타 1,000 h × 25) → R = 100,000, 우리 재구성 30,000, RecF = 1.2 → **36,000 Nm³**.
- 사례 B: Q = 60,000 Nm³, 우리 300 t / 전체 1,000 t → **18,000 Nm³**.

## 4. 화면과 서식

### 4-1. 지도 4단계(연료) · 대화 모드
- 연료 입력 아래에 「외주처에서 하는 공정이 있나요?」 — 있으면 외주처·공정 종류(위 5종)·방법을 고르고 방법별 입력칸(§3)을 보인다. 계산 결과(우리 몫)를 바로 보여 주고 「저장」으로 연료 배출원을 만든다.
- 공정 종류가 「전기도금」이면 입력 대신 경계 밖 안내(기존 STEEL_BOUNDARY_NOTE)를 보인다.
- 「다크로·전기아연도금」을 구분하는 질문: 「전류로 피막을 입히나요?」 예 → 전기도금(경계 밖), 아니오 → 코팅(경계 안). 근거 문장을 `technique_evidence`에 적게 한다(ISO 10683 = 비전해 아연 플레이크, ISO 4042 = 전해 코팅을 칸 도움말로 소개).

### 4-2. 활동자료 서식 — 새 시트 「13_외주공정」
컬럼: 외주처 · 공정 종류 · 우리 공정(제품) · 연료 종류 · 계산 방법 · 외주처 총 연료량 · 설비 연료량 · 우리 처리량(t) · 설비 전체 처리량(t) · 설비 목록(이름/시간/소비율을 `;`로) · 근거 · 증빙.
- 기존 서식(1~12시트)을 올려도 그대로 동작한다(시트가 없으면 건너뜀). 서식 버전은 올리지 않는다.
- 5_구매강재 시트 머리말에 「외주 임가공으로 돌아온 부품은 여기에 적지 않습니다 → 13_외주공정」을 적는다.

### 4-3. 산정보고서 · 모니터링 계획 · 할 일
- 산정보고서: 「외주 공정 (EC Q&A 4.31 — 1차 사업장 공정으로 처리)」 표(외주처·공정·방법·우리 몫·근거). 추정이면 「확인 필요」 표시.
- 모니터링 계획: 방법론에 「외주 공정의 배출 결정 방법」과 부속서 II A.5 22(g)(외주 공정 통제) 항목이 들어갈 자리를 만든다.
- 할 일: 외주처에 요청할 자료 목록(연간·월별 고지서, 가스 사용설비 목록과 계량기 계통도, 설비별 정격 소비율, 설비별 가동시간, 우리·타사 처리량, 소성·경화 온도·체류시간·코팅 횟수, 배분 계산서와 총량 대사표)을 항목으로 낸다.

## 7. 정한 것과 남은 것

**정했다(근거가 있다)**: 외주 배출은 우리 공정의 연료 배출원으로 저장 · 전구물질 칸에 넣지 않는다 · 경계 밖 공정은 받지 않는다 · 추정은 근거 필수와 「확인 필요」 · 백업 형식 변경 없음.

**남았다**(사용자·검증인 판단):
1. 다크로를 coating으로 보는 분류의 최종 수용 여부 — 앱은 「전류 사용 여부」 질문과 분류 근거 칸으로 증빙만 남긴다(규정에 정의가 없다).
2. RECONSTRUCTED의 재구성 합과 고지서 총량이 얼마나 어긋나면 막을지(위 20%는 임시값) — 검증 사례가 쌓이면 조정.
3. 외주처가 우리 부품만 단독 처리하는 설비(전용 계량)가 흔한 경우의 기본 입력 방법(METERED_LINE의 간단한 경로)을 화면 첫 선택지로 둘지.
