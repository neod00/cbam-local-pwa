작성: 2026-10-07. 대상: 「CBAM Local — 귀속·할당 기능 개선 개발 지시서」(사용자가 붙여 넣은 제안서). 제안서가 스스로 요구한 순서(코드 확인 → 비교 → 구현)를 따른 첫 단계다.
근거: 코드 직접 확인(`allocation-rules.ts`·`calculation-engine.ts`·`eu-template-export.ts`·`local-db.ts`·`fuel-allocation.ts`·`electricity-allocation.ts`·`measurable-heat.ts`·`energy-split-summary.ts`), `execution-plans.md`, `ux-concept-v4.md` §8-1.
**정정**: 이 분석 전에 한 말 중 하나가 틀렸다 — 「배분 합계 100% 검사(V08)가 전체 단위로는 없다」고 했지만, 엔진에는 사용자 지정 배분 합계와 **구매 강재의 제품별 귀속 합계 ≠ 소비량** 검사가 이미 있다(`calculation-engine.ts`). 진짜 빈 곳은 검사가 아니라 **한눈에 보는 곳**이다.

## C. 이번 작업에서 실제로 필요한 변경

1. **귀속·할당 점검표(V01~V08)** — 위 점검들은 모두 있지만 **문제가 있을 때만 경고로 흩어져** 나온다. 통과한 것이 보이지 않아 「무엇이 확인됐는지」를 알 수 없다. → 엔진 경고에 점검 종류(`check`)를 붙이고(계산 불변), 할 일 화면에 ✓/⚠/✕ 한 표로 모은다. **(이 PR)**
2. **Emission Trace** — 최종 SEE를 구성 요소 → 원천(배출원·계수 출처·고지서 증빙)으로 거슬러 보는 읽기 전용 화면. 결과 화면의 분해와 보고서 일부가 있으나 한 흐름으로 따라갈 수 없다. **(다음 PR)**
3. 복수 생산경로·`process_type`은 **규정 원문 확인 후** 결정(아래 D·F).

## D. 변경하지 않을 기존 기능 / 제안서 항목 중 채택하지 않는 것

- **`AllocationDecision` 새 저장소**: 방법·기준값·증빙·사유는 이미 `shared_meter`(basis·note), `electricity_shared_meter`, `heat_consumption`(basis·note), `manual_allocation_reason/evidence`에 저장돼 있다. 새 저장소는 같은 사실을 두 곳에 두고 백업 형식을 올린다. 제안서 AC10도 「저장 **또는 재구성**」이라 했다 → Emission Trace가 기존 필드에서 재구성한다.
- **`MOLAR_RATIO`·`WASTE_GAS_RULE`·CHP 방법 목록**: 이 앱은 철강 가공업체용이고 고로 일관제철은 지원하지 않는다. 목록에 올리면 지원하는 것처럼 보인다.
- **새 5단계 `/allocation` 작업실**: 지도 8단계·`/talk`·`/todo`와 흐름이 넷이 된다. 대신 할 일 화면에 점검표를 둔다.
- **MASS/MANUAL 선택을 기본 화면에서 제거**: 사용자 지정은 이미 예외·사유 필수다. 기본값(질량)은 사용자가 고른 방식이 아니라 규정의 기본값이라는 점을 화면에서 분명히 하는 정도로 충분하다(이번에는 손대지 않음).
- EU 내보내기 수식·엑셀 구조, `.cbam` 형식, 엔진 산술, 미지원 항목의 0 처리 금지 — 그대로.

## E. 데이터 Migration 필요 여부

이번 범위(점검표·Emission Trace)는 **필요 없다**. 새 필드·저장소·백업 형식 변경 없음(`LocalCalculationWarning.check`는 계산 중에만 있는 선택 필드이며 저장되지 않는다). 복수 경로(`production_routes[]`)를 하게 되면 그때 필요하다.

## F. 위험요소

| 위험 | 대응 |
|---|---|
| 엔진 파일(`calculation-engine.ts`)을 건드린다 | 경고 호출 18곳에 선택 인자(`check`)만 더했다. 게이트가 「태그를 걷어낸 기준 엔진」과 결과 전체(숫자·경고 문장)가 같음을 두 시나리오로 확인하고, 태그 수를 고정한다 |
| 점검표가 엔진 문장 머리말(「차단:」·「확인 필요(자료):」)에 기대 심각도를 정한다 | 머리말은 이미 엔진·내보내기 점검이 쓰는 약속이다. 배분 합계·귀속 누락은 문장과 무관하게 「수정 필요」로 고정 |
| 점검표가 「✓」를 과신하게 한다 | 각 줄의 제목이 무엇을 확인했는지 정확히 말한다(예: V06은 「귀속이 지워진 라인을 가리키지 않음」). 확인하지 않은 것은 ✓로 보이지 않는다 |
| 복수 생산경로: 같은 기능단위 안 여러 경로를 한 공정으로 묶는 것이 규정상 요구되는지 | 원문 확인 전 구현 금지. 현재 엔진은 이미 「경로가 달라도 단일 공정」이라고 경고한다(`ROUTE-01`) |
