# Free License Strategy

무료 라이선스는 사용자를 막기 위한 장치가 아니라 배포 관리, 공지, 업데이트, 문의 대응을 위한 장치다.

## Product Boundary

- CBAM 입력 데이터는 계속 로컬 우선으로 처리한다.
- 라이선스 서버는 사용자 식별, 라이선스 상태, 공지, 업데이트 정책만 관리한다.
- 라이선스 확인은 생산량, 배출량, 전구물질, 공급업체 자료, EU 템플릿, `.cbam` 백업 파일을 수집하지 않는다.

## Allowed Data

- 이메일
- 회사명
- 담당자명
- 국가
- 업종 또는 CBAM 품목군
- 약관 동의 시각
- 라이선스 키
- 앱 버전
- 마지막 라이선스 확인 시각
- 공지 확인 여부

## Forbidden Data

- 생산량
- 배출량
- CN별 산정값
- 전구물질 자료
- 공급업체 자료
- EU 템플릿 파일
- `.cbam` 백업 파일
- 산정 결과 원자료

## License States

- `UNREGISTERED`: 등록 전. MVP에서는 사용을 막지 않는다.
- `FREE_ACTIVE`: 무료 라이선스 등록 완료.
- `OFFLINE_ALLOWED`: 최근 확인 이력이 있어 일정 기간 오프라인 사용 가능.
- `RECHECK_REQUIRED`: 장기간 확인이 없어 재확인이 필요.
- `BLOCKED`: 악용, 재배포, 약관 위반 등으로 차단.

## PWA Behavior

- 설정 화면에 무료 라이선스 섹션을 둔다.
- 초기 구현은 mock 검증과 로컬 저장만 제공한다.
- 라이선스가 없어도 MVP 계산 기능은 막지 않는다.
- 라이선스 UI는 “CBAM 산정 데이터는 서버로 전송하지 않습니다”를 명시한다.
- 오프라인 상태에서는 마지막 정상 확인 시각을 기준으로 일정 기간 사용을 허용한다.

## Admin Behavior

관리자는 다음 정보만 본다.

- 등록 사용자
- 회사/담당자 연락처
- 라이선스 상태
- 앱 버전
- 공지/업데이트 정책 수신 상태

관리자는 CBAM 업무 데이터, 산정 결과, EU 템플릿, `.cbam` 백업을 보지 않는다.

## Rollout Rule

무료 PWA의 라이선스 기능은 차단 장치가 아니라 배포 관리 장치로 시작한다.

1. MVP 공개 전에는 mock 등록과 정적 업데이트 manifest만 사용한다.
2. 원격 라이선스 API를 붙이더라도 `UNREGISTERED`, `RECHECK_REQUIRED`, `OFFLINE_ALLOWED` 상태에서는 계산과 백업을 계속 허용한다.
3. `BLOCKED`는 악용 또는 재배포 차단용으로만 사용하고, 기존 로컬 `.cbam` 백업 접근을 막지 않는다.
4. 강제 업데이트가 필요한 경우에도 사용자에게 먼저 `.cbam` 백업을 만들 수 있는 경로를 제공한다.
5. 어떤 단계에서도 CBAM 산정 데이터, EU 템플릿, 백업 파일을 라이선스 서버로 전송하지 않는다.
