# 공개 준비 상태 점검 (2026-10-17)

무료 로컬 우선 PWA를 외부에 공개하기 전의 상태를 한 장으로 모은다. 계산·기능은 개발 쪽에서 닫을 수 있는 것이고, 운영자 정보·법무 검토·공개 결정은 사람이 해야 한다. 절차의 세부는 `docs/pre-release-checklist.md`, `docs/v0.1.0-beta-go-no-go-record.md`, `docs/first-deployment-runbook.md`를 따른다.

## 1. 개발 쪽 — 닫혀 있는 것

| 항목 | 상태 | 근거 |
|---|---|---|
| 자동 점검 | 통과 | `npm run verify`(60여 개 점검 + 빌드). lint 오류 6건은 `artifacts/*.cjs`의 기존 건이며 앱 코드가 아니다 |
| 계산 엔진·EU 엑셀 | 통과 | 시험 업체 6곳(run35~run40: 풍강·진합·S&W·KPF형)의 엑셀 서식을 8단계까지 돌려 EU 엑셀을 Excel로 전체 재계산 → 오류 셀 0 |

## 2. 사람이 정해야 하는 것 — 공개를 막고 있는 것

`npm run release:status`가 지금 `NOT READY`라고 말하는 이유는 모두 여기에 있다.

1. **운영자 정보 7칸**(`src/lib/operator-info.ts`): 운영 주체, 사업자등록번호(또는 「해당 없음」), 주소(또는 「요청 시 제공」), 개인정보 보호책임자, 전속 관할 법원, 약관 시행일, 개인정보 처리방침 시행일. 값을 지어내지 않는다 — 비어 있으면 약관·개인정보 화면이 「배포 전 확정 필요」라고 말한다.
2. **법무 검토**: `/terms`와 `/privacy`를 운영자 정보를 채운 뒤 검토. 무료 라이선스 등록이 이메일·회사명·담당자명 등을 서버(Neon, 미국)로 보내므로 개인정보 국외 이전 안내가 사실과 맞는지가 핵심이다.
3. **공지 문구 승인과 Go/No-Go 기록**: `docs/free-pwa-release-announcement-draft.md`, `docs/free-pwa-terms-draft.md`의 상태 값을 승인으로 바꾸고 `docs/v0.1.0-beta-go-no-go-record.md`를 채운 뒤 `npm run release:approval`이 통과하는지 확인.

위 셋을 사람이 끝내기 전에는 앱을 외부에 공개하지 않는다(개발 쪽에서 대신할 수 없다).

## 3. 공개 전에 알아 둘 한계 (사용 안내에도 같은 내용)

- **철강 제품만** 산정한다. 다른 품목군과 고로 일관제철은 지원하지 않는다.
- **한 프로젝트 = 한 해 = 한 사업장.** 사업장이 여럿이면 사업장마다 프로젝트를 따로 만든다(사업장 화면이 EU 파일에 나가는 사업장을 표시한다). 다음 해는 「새 프로젝트」로 시작하고 지난해 자료는 `.cbam` 백업으로 보관한다.
- **외주처가 쓴 전기(간접배출)** 는 아직 입력을 받지 않는다. 연료 몫만 받는다.
- **전력 배출계수**는 앱이 표를 내장하지 않는다(IEA 비상업 라이선스) — 2025/2621 부속서 II 표에서 찾아 직접 입력한다.
- **마크업 반올림**: 정정판 기본값 파일에 마크업 열이 없어 앱이 총량 × (1+비율)로 계산한다. 레지스트리의 반올림 규칙은 규정 전문에 없어 확인되지 않았다.
- **제3자 검증 자체와 최종 제출 책임은 앱이 대신하지 않는다.** 앱은 검증을 받을 수 있는 수준의 산정과 근거 정리까지 돕는다.
- 대화 모드에는 외주 공정 입력이 없다(지도 화면과 엑셀 서식에는 있다).

## 4. 시범 사용에 대하여

개발 중 모든 시험은 가상 자료로 개발 쪽이 눌러 본 것이다. 외부 사용자에게 시험을 맡기는 방식은 쓰지 않기로 했으므로(프로젝트 방침), 공개 전 실제 자료 확인은 **운영자 본인(또는 소속 컨설턴트)이 실제 업체 자료로 한 번 돌려 보는 것**으로 대신한다. 이때 `docs/consultant-guide-ko.md`의 순서를 쓰면 된다.

## 5. 배포 절차 포인터

- 배포 방법: `docs/pwa-deployment-guide.md`, `docs/first-deployment-runbook.md`
- 배포 직전 자동 점검: `npm run verify`(`verify:deployment`가 회사 자료·`.env`·`.cbam`·Excel·PDF가 저장소에 딸려 들어가지 않았는지, `verify:pwa-release`가 PWA 요건을 본다). 서비스 워커 캐시 이름(`public/sw.js`의 `CACHE_NAME`)은 데이터 파일이 바뀌면 올린다.
