## P2-run10-01 — 배출원 유형을 바꾸면 사람이 고른 계수 출처가 지워진다

**무엇**

4단계 「배출원 추가」에서, 실제 클릭으로 재현:

1. 「계수 출처 유형」을 **「국가 인벤토리·공공 통계」**로 고른다
2. 「어떤 배출원인가요?」를 「도시가스」 → 「유류·기타」로 바꾼다
3. 계수 출처 유형이 **「EU/IPCC 기본계수」로 조용히 바뀐다**

바로 그 칸 아래 도움말은 이렇게 적혀 있다:

> 이 계수가 어디서 온 값인지. 모르면 「분류 전」으로 두세요 — **앱이 대신 정하지 않습니다.**

앱이 방금 대신 정했다.

**왜 문제인가**

세 겹이다.

1. **문안과 행동이 어긋난다.** 같은 화면에서 약속하고 어긴다. 이 프로젝트가 반복해서 고쳐온
   실패 모양(문서·화면이 자기가 한 말을 부정한다)과 정확히 같다.

2. **의도한 선택을 지운다.** 자리값은 *건드리지 않은* 칸에 넣는 것이지, 사람이 고른 값을
   덮어쓰는 것이 아니다. 배출계수·발열량을 유형에 맞게 갈아주는 것은 옳다 — 그 값들은 연료
   종류에 매인 숫자다. 그러나 계수 출처 유형은 **누가 그 숫자를 보증하는가**에 대한 진술이고,
   연료 종류가 바뀐다고 보증 주체가 바뀌지 않는다.

3. **덮어쓰는 방향이 나쁘다.** 덮어쓴 값은 항상 `UNCLASSIFIED`가 아닌 값이고, 그 순간
   준비도 경고(「배출계수 출처 유형이 분류되지 않았습니다」)가 **꺼진다.** 사용자가
   「모르겠다」고 말했는데 앱이 「국가 인벤토리다」 또는 「공급사가 보증했다」로 바꾸고,
   확인하라는 경고까지 없애는 것이다. `P2-run09-01`이 고친 결함이 한 걸음 옮겨 남았다.

**어디**

`src/components/guided/panels.tsx:1161-1171` — 유형 `onChange` 안:

```ts
if (next) {
    setFactor(String(next.defaults.emission_factor_tco2e_per_unit));
    setNcv(String(next.defaults.ncv_gj_per_unit));
    setFactorSource(next.defaults.factor_source_type);   // ← 이 줄
}
```

주석은 「남겨두면 물질수지 칸에 연료 계수가 남는다」로 앞 두 줄을 정당화한다. 맞는 말이지만
세 번째 줄에는 그 논거가 적용되지 않는다.

**고치는 방향**

사람이 손댄 적 있는지 기억해서, 손댄 뒤에는 덮어쓰지 않는다.

```ts
const [factorSourceTouched, setFactorSourceTouched] = useState(false);
// select onChange: setFactorSourceTouched(true)

// 유형 변경 시:
if (!factorSourceTouched) {
    setFactorSource(next.defaults.factor_source_type);
}
```

폼을 새로 열거나 수정을 시작할 때 `false`로 되돌린다.

더 단순한 대안: **세 번째 줄을 지우고 초기값을 항상 `UNCLASSIFIED`로 둔다.** 유형별 자리값을
미리 고를 이유가 애초에 약하다 — 앱은 그 계수가 어디서 왔는지 알 방법이 없다. 도움말이
약속하는 것도 이쪽이다. 「분류 전」로 시작하면 준비도 경고가 사람을 분류로 이끈다.

두 번째 안이 더 낫다고 본다. 자리값의 이득(클릭 한 번 절약)보다 손해(근거 없는 출처 주장이
저장되고 경고가 꺼짐)가 크다.

**회귀 게이트 제안**

`scripts/verify-guided-panels.mjs`에 — 유형 `onChange` 본문에 `setFactorSource(`가
**없어야** 한다(또는 `touched` 가드 안에만 있어야 한다). 지금은 이 동작을 막는 검사가 없다.

**등급이 P2인 이유**

산정값은 틀리지 않는다. 보고서는 `factor_source_type`을 인쇄하지 않으므로 거짓 문장이
문서로 나가지도 않는다. 저장된 사실이 틀리고 경고가 꺼지는 문제이며, `P2-run09-01`과 같은 등급이다.

## PR #47이 스스로 만든 결함 10건 — 별도 검토 발견 (수정 완료)

보고서 문안을 고친 사람이 그 문안을 검토하면 같은 맹점을 두 번 지난다. 그래서 R6 수정본을
**별도 검토에 넘겼고**, 숫자·등록부 45건·경고 15건은 손으로 세어 맞다고 확인받은 대신
**새 결함 10건**을 돌려받았다. 전부 이번 수정이 만든 것이다.

가장 아픈 두 건:

### 같은 커밋이 9장에서 고친 실패를 5장에서 되풀이했다 (P2)

9장에서 「전구물질 0건인데 기본값을 찾지 못했다」는 **가짜 자료 공백**을 없앴다.
그런데 같은 커밋의 5.3장 고철 문단이 **가짜 규정 공백**을 새로 만들었다:

> 고철·철스크랩(CN 7204)은 … 본 산정에서 전구물질로 가산하지 않았다. … **확인 필요(규정).**

이 프로젝트엔 고철이 **입력된 적이 없다.** 하지 않은 판정을 서술하고, 존재하지 않는 자재에
대한 규정 공백 1건을 14.1 등록부에 올렸다(5장 3건 → 4건). 옛 문안에는 그 표기가 없었다.

**고침**: 고철이 실제로 입력됐을 때만 쓴다(`hasScrapPrecursor`).

### 13장이 「4건」이라 말하는데 표에는 6칸이 비어 있다 (P2)

`sourceGapCount`가 **G5 경고 수**를 셌는데, 6.2.2 게이트는 배출원 1건당 경고 1건을 내면서
NCV·EF **두 칸**을 함께 덮는다. 실제 빈 칸은 6.2.2에 4개(코크스 NCV/EF + 도시가스 NCV/EF),
7장에 2개 = **6개**. 그 문장이 「제14.1장 등록부」를 가리키므로, 대조하려는 독자가 멈춘다.

**고침**: 경고가 아니라 빈 칸을 센다. 문서가 「6건」으로 바뀌었다.

### 결과

- 등록부 **45건 → 43건** (줄어든 2건이 정확히 가짜 공백 둘)
- 13장 출처 건수 **4건 → 6건** (실제 빈 칸과 일치)
- 변형 시험 **34종 전부 잡음, 생존 0** — 첫 판에서 「9장 중복」 게이트가 죽어 있었고
  변형 시험이 그걸 잡았다(픽스처가 워크북 연결본이라 미연결 분기를 안 지났다)

### 남길 교훈

**같은 커밋 안에서 A장을 고치면서 B장에 같은 결함을 만들 수 있다.** 고철 건이 정확히 그 모양이다.
수정 후 자기 문서를 다시 읽을 때는 「내가 방금 없앤 실패가 다른 장에 새로 생기지 않았는가」를
따로 물어야 한다. 이번엔 별도 검토가 그것을 물었다.

## 참고 — 철회한 지적

「수정 화면에서도 유형을 바꾸면 저장된 출처가 덮어써진다」고 처음 관찰했으나 **사실이 아니다.**

수정 중에는 유형 드롭다운이 `disabled`이고(`panels.tsx:1160`), 「유형은 바꿀 수 없습니다.
종류가 통째로 달라졌다면 지우고 다시 등록하세요」라는 안내까지 붙어 있다. 내가 합성 이벤트로
`disabled`를 우회해 관찰한 것이고, 실제 사용자 조작으로는 일어나지 않는다.

기록해 두는 이유: **자동화로 검사할 때 `disabled`를 우회하면 없는 결함을 만들어낸다.**
Playwright의 `selectOption`처럼 실제 사용자 제약을 지키는 방법으로 재확인해야 한다.
