# 사용 일지 — 2026-07-15_run07 (bridge + ③ SAD 비교)

**담당**: 씨밤이 (CBAMY) | **모드**: 회귀 + 신기능 검증 (트리거 대기 백로그 2건 착수)
**대상 변경**:
- **bridge (간접 SEE 2입력 분리)** — 공급사가 간접분을 전력사용량(MWh/t)·계수(tCO₂e/MWh)로 따로 주면 그 실제 분해를 저장(`indirect_electricity_mwh_per_t`·`_factor_tco2e_per_mwh`)해 EU `E_PurchPrec` L+36/L+37에 그대로 기재. 미입력 시 현행 synthetic(사용량 1×간접값) fallback.
- **③ SAD 비교 (전구물질 단위)** — 전구물질 패널 "실측 vs 기본값 비교(비용 판단)": 현재 CN의 공식 DV를 조회해 실측 총 SEE와 나란히 비교, t당·소비량 기준 차이와 유리/불리 판정(읽기전용).

**검증**: 전체 `npm run verify`(build+16스크립트+lint+routes) + 브라우저(Playwright + IndexedDB 주입 + DV 참조 주입)

> 규정 근거: 공식 나사·너트 예제의 `E_PurchPrec (e)`는 간접 SEE를 **전력사용량·계수 2개 입력**으로 받는다(예: 0.346 MWh/t × 0.590 tCO₂/MWh). DV는 보수적으로 높게(markup) 잡히므로 실측이 유리한 경우가 많다(Guidance 6.1.5).

## 진행 기록

**[bridge — 채움]** 전구물질 패널 "간접분을 전력사용량×계수로 입력"을 펼쳐 전력사용량 **0.346**, 전력계수 **0.590**을 넣으니 미리보기가 "= 간접 SEE **0.2041**"로 계산됐고, "간접분 칸에 채우기"를 누르니 간접분 칸이 **0.20414**로 채워졌다(0.346×0.590 정확). 저장 후 IndexedDB 레코드에 `indirect_see_tco2e_per_t=0.20414` + `indirect_electricity_mwh_per_t=0.346` + `indirect_electricity_factor_tco2e_per_mwh=0.59`가 모두 기록됐다.

**[bridge — export 실측 분해]** `verify-eu-export.mjs`에 두 경로를 어서션으로 고정: (a) bridge 값이 있으면 L50=**0.346**·L51=**0.590**(실제 분해), (b) 없으면 L50=**1**·L51=**0.25**(synthetic fallback). 둘 다 PASS. → 검증자가 "전력 1 MWh/t?"로 오해할 여지를 제거.

**[③ SAD — 판정]** 선재 CN **72131000**, 직접 1.80·간접 0.30, 소비량 1,050t으로 "기본값과 비교"를 누르니:
- 지금 실측: 직접 1.8 · 간접 0.3 · **총 2.1**
- EU 기본값: 직접 2.33 · 간접 미제공(0) · **총 2.33** (출처: South Korea / **7213** markup 포함, CN 4자리 접두 매칭)
- 판정: **"실측이 t당 0.23 낮습니다 — 유리. 실측 자료를 확보·유지하세요 (소비량 1,050t 기준 총 241.5 tCO₂e 절감)."** (2.1−2.33=−0.23, ×1,050=241.5 정확)

**[엔진 회귀-안전 — 핵심]** 전구물질 저장 후 지도가 "③ 전구물질 — 직접 1,890 · 간접 **214.3**"로 표시(=1,050×0.20414). 즉 **엔진은 bridge 분해(0.346/0.590)를 무시하고 단일 간접 SEE(0.20414)만 사용**한다. 기준 SEE = **2.01**(=자체 직접 0.12 + 전구물질 직접 1.89, Annex II direct-only로 간접 제외). `verify-local-calculation.mjs`도 통과 — 새 필드는 계산 엔진에 닿지 않는다.
