| 하지 않는 것 | 규정 원문을 스스로 해석하지 않는다. 앱이 안내하는 대로 따라가되, **의심스러우면 세미나 자료의 기억과 대조**한다. 값을 지어내지 않는다 — 모르면 "모른다/확인 필요"로 남긴다 |

### 담당자가 이 앱에 기대하는 것 (평가 관점)
1. **혼자 끝낼 수 있는가** — 어디서 막히고, 막혔을 때 앱이 다음 행동을 알려주는가
2. **내 자료(고지서·ERP) 형태 그대로 넣을 수 있는가** — kWh, Nm³, L, kg/pcs, 월별 합계
3. **결과를 믿고 상사에게 설명할 수 있는가** — 산식·근거·출처가 보이는가, 검증인이 물으면 답할 수 있는가
4. **고객사가 요구한 산출물이 나오는가** — EU Communication Template 복사본 + 우리 회사용 보고서
5. **다음 해에도 재사용할 수 있는가** — 백업·복원, 기간 갱신
6. **데이터가 밖으로 나가지 않는가** — 회사 보안팀이 물어볼 것

## 4. 생산공정 (공장 실제 모습)

```
[STS 선재·와이어 매입] ─┐
                        ├─ 냉간압조(헤더) → 전조(나사산) → 세척·산세·부동태 → 검사·포장 → 출하
[탄소강 CHQ 와이어 매입] ┘                                ↑ 탄소강만: 열처리로(QT, 도시가스) → 외주 도금
```

| 설비 | 사용 제품 | 에너지 | 계량 |
|---|---|---|---|
| 냉간압조기 24대, 전조기 18대 | STS·탄소강 **공용** (라인 교체 사용) | 전력 | **한전 계량기 1개(공장 전체)**. 라인별 서브미터 없음 |
| 열처리로(연속 QT로) 1기 | **탄소강 전용** | 도시가스 | **서브 계량기 있음** (열처리로 전용) |
| 세척수 온수 보일러 | STS·탄소강 공용 | 도시가스 | 별도 계량기 없음 → 총 사용량 − 열처리로 서브미터 |
| 산세·부동태 라인 | STS 전용 | 전력(펌프·배기) + 질산·불산 | CO₂ 배출 없음 |
| 지게차 4대 | 공용 | 경유 | 주유 전표 |
| 사무동·기숙사 | — | 전력(공장 계량기에 포함), 등유 난방(소량) | 등유는 10 드럼(2,000 L) — "이것도 넣어야 하나?" |

9. 지게차 경유·사무동 등유도 넣나
10. 우리가 내는 기후환경요금은 탄소가격으로 인정되나

## 9. 실사용 규칙 (페르소나 운영 규칙)

- **앱 주소**: `http://127.0.0.1:3000` — 반드시 `127.0.0.1`을 쓴다(`localhost`와 저장소가 분리되어 있어 빈 상태에서 시작한다).
- **처음 쓰는 사용자처럼** 행동한다. 홈에서 시작해 앱이 안내하는 순서를 따른다. 도움말·안내문을 실제로 읽고, **안내가 없거나 틀리면 그 사실을 기록**한다.
- 자료는 §5·§6의 **원본 형태**(kWh, Nm³, L, t)로 넣는다. 앱이 단위 변환을 요구하면 담당자 수준에서 할 수 있는 만큼만 하고, 못 하면 막힌 것으로 기록한다.
- 값을 지어내지 않는다. 시나리오에 없는 값은 "모름"으로 두고 앱이 어떻게 반응하는지 본다.
- **결정 지점**(탄소강 포함 여부, 배분 방식, NCV, 전력 EF, 기본값, 스크랩, 경유·등유)마다 담당자가 무엇을 근거로 무엇을 골랐는지 1인칭으로 기록한다.
- 끝까지 간다: 결과 → 시나리오(인증서 비용) → EU 템플릿 복사본 생성 → 산정보고서(Word) → `.cbam` 백업 → 복원 확인.
- 다운로드 파일·스크린샷은 `cbamy/runs/2026-09-16_run11/downloads/`, `.../screenshots/`에 보관한다.
- 운영자 전용 파일 `scenarios/sts-fastener-daeil-app-checks.md`와 이전 run의 `improvement-suggestions.md`는 **읽지 않는다.**
